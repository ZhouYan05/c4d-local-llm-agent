## 4. Agent 主循环验证

一次真实运行产生 8 条 trace 步骤，顺序与设计一致：

```
load_model → plan → tool:geocode → generate_markers
→ tool:disperse_markers → tool:validate_markers → tool:render_map → self_check
```

- Step1 规划：模型解析意图，输出 Plan（任务/地区/中心/类别/marker 数量）。
- Step2 地理编码：`geocode` 命中离线地名库，返回中心 `34.504, 113.7466`（源=gazetteer）。
- Step3 生成 POI：模型产出 6 个 MarkerCard（名称/类别/中文简介）。
- Step4 **坐标分散**：`disperse_markers` 检测到 6 个点坐标重合，做确定性环形铺开（见第 6 节）。
- Step5 校验：`validate_markers` 未丢弃任何点（`dropped: []`）。
- Step6 渲染：`render_map` 写出交互式 Leaflet HTML。
- Step7 自检：模型用一句话总结。

## 6. 关键失败与修正（可复核）

1. **坐标全重叠**：首轮 6 个 POI 共用同一中心坐标，地图上完全重叠。
   先改**提示词**（要求 ±0.004° 内不同方向分散、4 位小数）——重跑后 1B 模型**仍**输出同一坐标，
   证明是模型能力上限。遂新增确定性工具 `disperse_markers`：仅对坐标重合点环形铺开，
   在 trace 中如实记为 `tool:disperse_markers`（moved=6）。
2. **坐标越界/重复**：`validate_markers` 负责过滤 + 重采样补齐，本轮 `dropped=[]`。
